# AGENTS.md — typelizer (Elixir)

Rules for every contributor and every coding agent in this repository.
`CLAUDE.md` is a symbolic link to this file: edit `AGENTS.md` only.

## What this project is

**typelizer** — "Define once in Elixir. Generate everywhere in TypeScript."
An open-source (MIT) Elixir library for Phoenix apps. It gives you:

- a serializer DSL that is both the runtime serializer and the source of the types,
- TypeScript interfaces inferred from Ecto schemas (enums become literal unions),
- typed TypeScript route helpers generated from the Phoenix router,
- typed page props for Inertia.js pages,
- `mix typelizer.gen` to write the files and `mix typelizer.check` to fail on drift.

It is a clean-room port of the idea behind the Ruby gem
[skryukov/typelizer](https://github.com/skryukov/typelizer). Never copy its code;
credit it in the README.

## Non-negotiables

- **English only, everywhere.** Code, identifiers, comments, docs, README,
  CHANGELOG, test names, commit messages, error messages, issue and PR text.
  No other language, ever.
- **The repository contains only what a user of the library needs**: `lib/`,
  `test/`, `guides/`, `README.md`, `CHANGELOG.md`, `LICENSE`, `AGENTS.md`,
  `CLAUDE.md` (symlink), the mix/format/credo/dialyzer config and `.githooks/`.
  Never commit planning notes, kickoff prompts, task trackers, session logs,
  status files, TODO lists or scratch files. They live outside the repository.
- **No private context.** Never mention local paths, internal projects,
  clients, companies or people in code, docs or commit messages. Examples use a
  neutral `MyApp` / `MyAppWeb`.
- **This file is a rulebook, not a log.** Do not add dated entries or
  "what changed" notes here. Changes for users go in `CHANGELOG.md`
  (Keep a Changelog format, SemVer).
- **Never publish to Hex** (`mix hex.publish`) and never push a release tag
  without the maintainer's explicit approval.

```
├── typelizer/routes.ex          # Phoenix router → TS route helpers

└── mix/tasks/                   # typelizer.gen, typelizer.check

├── support/fixture_app/         # a small Phoenix app: router, schemas, serializers, pages

```

## Design rules

- **The public API is documented where users read it**: `@moduledoc` / `@doc`
  on every public module and function, plus the `guides/`. A change to the
  public API updates its docs and `CHANGELOG.md` in the same commit.
- Everything not meant for users carries `@moduledoc false`.
- **Deterministic output.** Same input → byte-identical files (stable ordering,
  fixed header "Generated by typelizer — do not edit", trailing newline).
  `mix typelizer.check` depends on it.
- **Fast at runtime.** Field lists and key transforms are resolved at compile
  time; no reflection per `serialize/1` call.
- **Compile-time errors over runtime surprises.** A computed attribute without
  `type:`, an unknown field or an unknown serializer is a `CompileError` with a
  message that says how to fix it.
- Optional dependencies (`phoenix`, `ecto`, `ecto_sql`, `inertia`) stay optional:
  guard the modules that need them with `Code.ensure_loaded?/1`.
- No runtime dependency beyond those. No network access in the library or in
  the tests.
- Support Elixir `~> 1.15` and OTP 26+.

## Quality gates (green before every push)

```
mix format --check-formatted
mix compile --warnings-as-errors
mix credo --strict
mix dialyzer
mix test --cover              # golden files, PostgreSQL and TypeScript tests; 90% coverage
mix docs                      # must build without warnings
```

The PostgreSQL tests need a local server; the TypeScript tests (tsc in strict mode
on the golden files, Prettier style, route helpers run in Node) need
`npm ci --prefix test/typescript`. Coverage counts library code only: the fixture
app in `test/support` is ignored (`test_coverage` in `mix.exs`).
Both are skipped with a notice when the tool is missing: install them before a push.

`mix check` (ex_check) runs them all. `.githooks/pre-push` runs `mix check`;
install it with `git config core.hooksPath .githooks`.
Golden files are regenerated only on purpose (`UPDATE_GOLDEN=1 mix test`) and
the diff is reviewed before commit. Never weaken a check to make it pass: fix
the code, or configure the check once with a written reason.

## Commits

Small, focused commits. English, imperative mood, a short subject line
("Add route helper generation"), a body when the reason is not obvious.
